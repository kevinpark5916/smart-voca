# 기획서 — 단어장 웹 앱

**파일 위치**: `docs/기획_251125_단어장 웹앱 v0.1.md`
**작성일**: 2026-11-25
**버전**: v0.1
**설명**: 단어 등록, 암기, 시험, 학습 통계를 갖춘 단어장 웹 앱을 학교 서버에 Docker 이미지로 올리는 과제의 목표, 범위, 일정, 기술 선택을 정리한다.

---

## 1. 목표

- 수업에서 만든 단어장 프로그램을 **웹 앱**으로 다시 만든다.
- 단어를 등록하고, 날짜별로 암기하고, 시험을 보고, 학습 진척을 본다.
- 이력은 **DB(SQLite)** 에 저장한다.
- 학교 서버에서 `/2026/voca-<학번>/` 주소로 실행한다.

## 2. 범위

| 구분 | 내용 |
|------|------|
| 포함 (기본) | 단어 등록·수정·삭제·검색, CSV 가져오기, 일차별 암기, 복습(다시·자주 틀린 단어), 시험(단답·4지선다·OX, 방향 선택), 시험 이력, 진도·정답률 추이·자주 틀린 단어 통계 |
| 포함 (설정) | 하루 학습량, 복습 수, 시험 문제 수, 가중치, 화면 테마 |
| 제외 (도전 미착수) | 로그인, 계정별 이력, 다른 계정 이력 보기 |
| 제외 | 듣기 시험, 달력, 엑셀 보고서, 발음(TTS), 알림 (데스크톱 PyQt 버전의 기능이며 과제 범위 밖) |

## 3. 기술 선택

| 항목 | 선택 | 이유 |
|------|------|------|
| 언어 | Python 3.13 | 수업 기본 언어, 기존 코드 재사용 |
| 웹 프레임워크 | Flask 3.1.3 | 가볍고 기존 서비스 계층을 그대로 씀 |
| 운영 서버 | gunicorn (워커 1, 스레드 1) | 진행 중 시험 상태가 프로세스 메모리에 있음 |
| 화면 | HTML + 바닐라 JS (외부 라이브러리 없음) | 빌드 단계 없이 서버에서 바로 동작 |
| DB | SQLite (`/data/voca.db`) | 과제 기본 요건 (PostgreSQL은 미협의) |
| 배포 | Docker 이미지, UID 10001 | 과제 서버 요건 (DR-18) |

## 5. 위험과 대응

| 위험 | 영향 | 대응 |
|------|------|------|
| Docker 이미지가 학교 서버에서 빌드되지 않음 | 시연 불가 | 점검 워크플로로 미리 확인. 로컬 Docker가 없어 GitHub에서 확인 |
| 점검 워크플로 파일을 받지 못함 | 제출 조건 미충족 | 학교 페이지에서 받아 `.github/workflows/`에 넣음 |
| 공개 서버에 인증이 없음 | 학습 기록이 누구에게나 보임 | 과제 요건상 불가피. 개인 학습 기록은 넣지 않는 것을 안내 |
| 시험 진행 상태가 서버 메모리에 있음 | 서버 재시작 시 진행 중 시험 소실 | 답한 문항은 DB에 남음. 1차 제출 전에 알림 |
| 과제 제공 CSV 파일 미확인 | 가져오기 형식 불일치 | 영단어,뜻 형식을 지원. 파일을 받으면 확인 |

## 2. 개발 원칙

1. **문서 먼저, 코드 다음**: 기능을 시작하기 전에 해당 FR의 시나리오(테스트 정의서)와 데이터 변경(데이터 설계서)을 먼저 정한다.
2. **추적성**: 모든 작업 단위는 FR/NFR ID를 가진다. 커밋 메시지와 테스트 이름에도 ID를 남긴다 (NFR-08). 현재 커밋 메시지에는 ID가 없으므로 **이후 커밋부터** 적용한다.
3. **파일 크기**: 200줄 이상 코드는 파일 단위로 나눠 구현한다. 500줄을 넘는 파일은 분리를 제안한다 (CLAUDE.md 원칙 5).
4. **데스크톱과 웹 동시 반영**: 서비스 계층에 넣은 기능은 두 화면에 모두 붙인다. 한쪽만 되는 기능은 계획에 이유를 적는다.
5. **승인 게이트**: 패키지 설치, 데이터 변경, 커밋, 배포는 사용자 승인 후 진행한다 (CLAUDE.md 자동 실행 원칙).

#### M1-1. 불러오기 전 백업 (NFR-04)

- **기능**: 단어 CSV 불러오기 전에 `data/backups/smartvoca_YYMMDD_HHMMSS.db`로 복사한다. 옵션으로 켜고 끈다.
- **모듈**
  - `src/storage/backup.py` (신규): `backup_database(db_path, backup_dir) -> Path`. SQLite 백업 API(`connection.backup`) 사용.
  - `src/app_context.py`: `import_words_csv`에 백업 옵션 추가.
  - `src/config/settings.py`: `backup_before_import: bool = True` 추가. 데이터 설계서 §7 갱신.
  - `src/ui/word_list_view.py`, `src/web/api_words.py`: 옵션 전달.
- **테스트**: `tests/test_backup.py` (백업 파일 생성, 원본 DB와 내용 동일, 백업 폴더 자동 생성)
- **문서 갱신**: 데이터 설계서 §7, §8 / 테스트 정의서 §6

#### M1-2. 단어 편집 (FR-09)

- **기능**: 추가, 수정, 삭제, 검색. 저장 전에 `word` 중복을 검사한다.
- **모듈**
  - `src/storage/word_repository.py`: `insert_word`, `update_word`, `delete_word`, `find_duplicate`
  - `src/services/word_service.py` (신규): 입력 검증과 중복 검사를 묶는다. 화면 두 곳이 같이 쓴다.
  - `src/ui/word_detail_dialog.py`: 보기 전용에서 편집 가능하게 바꾼다. 추가 대화상자는 `src/ui/word_edit_dialog.py` (신규).
  - `src/web/api_words.py`: `POST /api/words`, `PUT /api/words/<id>`, `DELETE /api/words/<id>` 추가.
  - `src/web/static/js/words.js`: 편집 화면 추가.
- **결정 필요**: 삭제한 단어의 학습·시험 기록 처리 (D-02)
- **테스트**: `tests/test_word_edit.py` (중복 거부, 수정 후 기존 시험 스냅샷 유지, 삭제 정책)
- **문서 갱신**: 데이터 설계서 §3.1 (삭제 정책), 아키텍처 §4, §6 (API), 테스트 정의서 §6

#### M1-3. 오답 단어장 (FR-11)

- **기능**: 오답률이 기준(기본 50%) 이상인 단어를 따로 보여 준다. 이 목록만으로 시험을 만든다.
- **모듈**
  - `src/storage/quiz_repository.py`: `wrong_rate_words(threshold, min_attempts)` 집계 쿼리 추가
  - `src/services/quiz_service.py`: 출제 원천을 "전체 / 오답 단어장"으로 받도록 `create_run` 인자 추가
  - `src/ui/quiz_view.py`, `src/web/api_quiz.py`: 출제 원천 선택
  - `src/ui/wrong_words_view.py` (신규), `src/web/static/js/wrong.js` (신규): 목록 화면
- **결정 필요**: 기준값과 최소 응답 수를 설정으로 둘지 (D-09). 기본안: 설정 `wrong_rate_threshold = 0.5`, `wrong_min_attempts = 2`.
- **테스트**: `tests/test_wrong_words.py`
- **문서 갱신**: 프로세스 설계서 (새 PL), 테스트 정의서

#### M1-4. 편집 거리 채점 (FR-10)

- **기능**: 정답 단어 길이가 5자 이상이면 편집 거리 1까지 정답으로 본다 (DR-04).
- **모듈**
  - `src/quiz/grader.py`: `edit_distance(a, b)`, 단답형 판정에 허용 규칙 추가
  - 정답 길이 기준은 `word` 원문 기준으로 한다 (뜻 쪽 정답에는 적용하지 않는다). 이 해석은 결정이 필요하다 (D-10).
- **테스트**: `tests/test_quiz_grading.py`에 케이스 추가 (길이 4 거부, 길이 5 거리 1 허용, 거리 2 거부)
- **문서 갱신**: 프로세스 설계서 PL-12, DR-04 상태

#### M1-5. TTS 발음 (FR-14)

- **기능**: `pyttsx3`로 단어를 읽는다. 영어 음성이 없으면 버튼을 비활성화한다.
- **사전 확인 (승인 필요)**: `pip install pyttsx3` (requirements.txt 추가). 설치된 음성 목록 확인 (R-2).
- **모듈**
  - `src/speech/tts.py` (신규): `Speaker` 클래스. 음성 목록 조회, 영어 음성 선택, 말하기. 엔진 객체를 생성자로 받아 테스트에서 가짜 객체를 쓴다.
  - `src/ui/study_view.py`, `src/ui/quiz_view.py`: 발음 버튼
  - `src/web/`: 브라우저 `speechSynthesis`를 쓸지, 서버 `pyttsx3`를 쓸지 결정 필요 (D-10). 기본안: 웹은 브라우저 음성 API 사용 (서버 음성 엔진 불필요).
- **테스트**: `tests/test_speech.py` (가짜 엔진으로 영어 음성 없음, 있음 두 경우)
- **문서 갱신**: 아키텍처 §4, §10, requirements.txt

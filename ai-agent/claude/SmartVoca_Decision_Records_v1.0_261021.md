## DR-01. GUI 라이브러리: PyQt6

- **배경**: Windows 데스크톱 GUI가 필요하며, 사용자가 Python과 PyQt를 지정했다.
- **대안**
  - PyQt5: 구버전이며 신규 기능 지원이 줄어드는 추세
  - PySide6: 공식 Qt 바인딩, LGPL 라이선스로 배포 조건이 유리함
- **결정 근거**: 사용자 지정 조건(PyQt)을 충족하면서 최신 버전이다. 자료가 풍부하다.
- **제약**: PyQt6는 GPL 또는 상용 라이선스다. 개인 사용과 비배포를 전제로 한다.
- **재검토 조건**: exe를 외부에 배포하는 시점 (FR-23). 그때 PySide6 전환을 검토한다. 화면 코드는 위젯 API가 거의 같아 전환 비용은 크지 않다.

## DR-02. 데이터 저장 방식: SQLite 단일 파일 + CSV 입출력

- **배경**: 암기·시험 이력을 저장하고, 기간별 집계 보고서를 만들어야 한다 (FR-07, FR-08).
- **대안**
  - CSV 파일 여러 개: 구현은 쉽지만 기간 집계와 오답 통계를 매번 직접 계산해야 함
  - JSON 파일: 구조는 유연하지만 집계 쿼리가 없어 직접 구현해야 함
  - SQLite 단일 파일: 집계 쿼리(GROUP BY, 기간 필터)를 바로 쓸 수 있음
- **결정**: 이력과 진도는 SQLite(`smartvoca.db`)에 저장한다. 단어 목록은 사용자가 교환하기 쉽도록 CSV로 불러오기·내보내기를 지원한다.
- **근거**: `sqlite3`은 파이썬 표준 라이브러리라 설치가 필요 없다. 보고서 집계가 SQL 한 번으로 끝난다.
- **결과**: 단어 원본은 CSV, 학습 기록은 DB로 역할을 나눈다. 불러오기 시 CSV의 `id`를 DB 기본키로 사용한다.

## DR-03. 출제 가중치 방식: 규칙 기반 가중 랜덤 (MVP)

- **배경**: 시험 출제는 "시험을 보지 않았거나, 오래됐거나, 자주 틀린 단어"를 높은 비중으로 포함해야 한다 (요구사항 5).
- **대안**
  - SM-2 간격 반복: 복습 시점을 정확히 계산하지만 설명과 튜닝이 어렵고 MVP 범위가 커짐
  - 가중치 규칙 (선택): 식이 단순하고, 값을 설정 파일에서 바꿔 보며 조정할 수 있음
- **결정**: MVP는 가중치 규칙 `w = 1 + W_NEW + W_OLD + W_WRONG × 오답률`을 사용한다 (Requirement Spec §4). 기본값은 `W_NEW=3`, `W_OLD=2`, `OLD_DAYS=7`, `W_WRONG=4`.
- **근거**: 요구사항 5의 세 조건을 직접 식으로 옮길 수 있다. 테스트하기 쉽다.
- **재검토 조건**: 2차 FR-15 (SM-2) 도입 시. 두 방식을 병행해 시험 결과를 비교하는 방안을 검토한다.

## DR-04. 단답형 채점 기준: 정규화 후 완전 일치 (MVP)

- **배경**: 단답형은 철자 오타를 어떻게 처리할지 정해야 한다.
- **대안**
  - 완전 일치: 구현이 단순하지만 1글자 오타도 오답 처리
  - 편집 거리(Levenshtein) 허용: 오타에 관대하지만 기준을 정해야 함
- **결정**
  - MVP: 앞뒤 공백 제거, 소문자 변환 후 완전 일치 비교
  - 1차 (FR-10): 단어 길이 5자 이상일 때만 편집 거리 1 허용
- **근거**: 짧은 단어(예: `a`, `is`)에 편집 거리를 적용하면 서로 다른 단어도 정답 처리될 수 있다. 길이 기준으로 이를 막는다.

## DR-05. 단어 데이터 출처: 개발팀 작성 초안 + 사용자 검토

- **배경**: 2000개 단어와 뜻·예문이 필요하다. 외부 사전이나 단어장의 문구를 그대로 가져오면 저작권 문제가 생길 수 있다.
- **대안**
  - 공개 단어 목록 사용: 출처 표기가 필요하며, 사용 조건을 확인해야 함
  - 사용자가 직접 제공: 가장 안전하지만 작업량이 큼
  - 개발팀이 빈도 높은 단어로 초안 작성 후 사용자가 검토 (선택)
- **결정**: 개발팀이 초안을 작성하고 사용자가 검토해 확정한다. 뜻과 예문은 직접 작성하며, 외부 사전 문구를 복사하지 않는다.
- **근거**: 저작권 위험이 낮고, 사용자가 검토하면서 오류를 줄일 수 있다.
- **제약**: AI가 작성한 뜻에 오류가 있을 수 있으므로 검토 과정이 필수다 (Charter R-1).

## DR-06. 일차별 진도 기준: CSV의 `id` 순서

- **배경**: N일차 단어를 어떤 순서로 나눌지 정해야 한다.
- **대안**
  - 빈도 순 또는 난이도 순: 효율적일 수 있지만 기준 데이터가 추가로 필요
  - `id` 순서 (선택): CSV 순서를 그대로 쓰므로 단순하고 예측 가능
- **결정**: `id` 오름차순으로 N개씩 나눈다. `level` 컬럼은 정렬에 쓰지 않고 표시용으로만 둔다.
- **근거**: 사용자가 CSV 순서를 바꾸면 진도 순서도 함께 바뀌므로 직접 제어할 수 있다.

## DR-07. 데이터 저장 경로

- **배경**: 개발 중에는 프로젝트 안에서 데이터를 확인하기 쉬워야 하고, 배포 후에는 사용자 데이터 폴더를 써야 한다.
- **결정**
  - 개발 단계: 프로젝트의 `data/` 폴더 (`data/smartvoca.db`, `data/words.csv`)
  - 배포 단계 (FR-23): `%APPDATA%\SmartVoca\`
- **근거**: 배포된 exe가 설치 폴더에 쓰기를 시도하면 권한 문제가 생기므로 배포 시 경로를 바꾼다.
- **제약**: `data/`는 `.gitignore`에 넣어 개인 학습 기록을 커밋하지 않는다 (CLAUDE.md 규칙 6).

## DR-08. 일차 전환 기준: 세션 단위

- **배경**: "하루 분량"을 날짜로 자를지, 암기 세션 단위로 자를지 정해야 한다. 날짜 기준이면 자정 전후나 중간에 끊긴 학습을 처리하기 어렵다.
- **대안**
  - 날짜 기준 (하루에 한 번만 다음 일차 생성): 같은 날 두 번 학습하면 목록이 꼬임
  - 세션 기준 (선택): 세션을 끝낼 때마다 다음 일차. 끝나지 않은 세션은 이어 한다
- **결정**: `study_session.finished_at`이 비어 있으면 그 세션을 이어 하고, 모두 끝나면 다음 실행 때 `마지막 일차 + 1`을 시작한다 (`StudyService.start_or_resume`).
- **근거**: 사용자가 언제 시작하든 진도가 어긋나지 않는다.
- **제약**: 하루에 여러 일차를 연달아 끝낼 수 있다. 하루 학습량을 강제하지 않는다.

## DR-09. 이력 없는 단어의 가중치

- **배경**: FR-05 식의 "마지막 시험 후 N일 경과" 항은 시험을 본 적 없는 단어에는 적용할 값이 없다.
- **결정**: 이력이 없으면 `1 + W_NEW`만 적용하고 `W_OLD`는 더하지 않는다 (`compute_word_weight`).
- **근거**: 이력 없음은 이미 `W_NEW`로 높게 잡혀 있어 중복 가산을 피한다.

## DR-10. OX형 정답·오답 비율

- **배경**: OX 문항에서 정답 짝과 오답 짝을 어떤 비율로 보여 줄지 정해야 한다.
- **결정**: 50%는 정답 짝(O), 50%는 다른 단어의 짝(X). 짝 후보가 없으면 정답 짝을 보여 준다 (`QuestionBuilder._build_ox`).
- **근거**: 한쪽으로 치우치면 항상 같은 답을 찍어도 맞힐 수 있으므로 비율을 고정한다.

## DR-11. 원본 단어 파일 보호

- **배경**: NFR-04는 원본 CSV를 덮어쓰지 않도록 요구한다.
- **결정**: 단어 CSV 저장 대화상자에서 `data/words.csv`를 고르면 저장을 막는다 (`WordListView._save_csv`). 불러오기는 DB에 반영만 하고 원본 파일은 건드리지 않는다.
- **제약**: 저장 경로 검사는 UI 단에서만 한다. 서비스 계층 `export_words_csv`에는 검사가 없다. 필요하면 서비스로 옮긴다.

## DR-12. 개발 환경 버전 (재검토 필요)

- **기록**: Python 3.15.0, PyQt6 6.11.0, pytest 9.1.1 로 개발·테스트했다.
- **위험**: Python 3.15는 최신 버전이라 일부 패키지 호환성 문제가 생길 수 있다. 프로젝트 안정성을 위해 3.12 또는 3.13 사용을 검토한다.
- **재검토 조건**: 다른 PC에서 설치가 실패하거나, 배포(FR-23) 전.

## DR-13. 되돌리기 범위: 현재 세션의 마지막 응답만

- **배경**: 잘못 누른 "알았음/다시"를 고칠 방법이 필요하다.
- **대안**: 여러 단계 되돌리기, 하루 전체 초기화, 마지막 응답 한 번만 되돌리기
- **결정**: 현재 세션에서 마지막으로 답한 카드 하나만 되돌린다 (`StudyService.undo_last`). 끝난 세션이면 다시 연다. 화면에 보이는 세션은 항상 최신이므로 이전 세션 기록은 건드리지 않는다.
- **근거**: 구현이 단순하고, 이미 다음 일차가 만들어진 뒤에는 이전 일차의 복습 목록이 바뀌지 않는다.

## DR-14. 다음 일차는 버튼으로 명시적으로 시작

- **배경**: 일차를 끝낸 뒤 앱을 다시 켜야만 다음 일차가 나오는 문제가 있었다.
- **결정**: 세션이 끝나면 "다음 일차 시작" 버튼을 보여 주고, 누를 때 `start_or_resume`을 호출한다. 자동 전환은 하지 않는다.
- **근거**: 사용자가 원하는 시점에 시작할 수 있고, 실수로 다음 일차가 만들어지지 않는다.

## DR-15. "다시" 버튼 의미: 내일 복습으로만 반영

- **결정**: 라벨을 "다시 보기 · 내일 복습"으로 바꾸었다. 같은 날 다시 나오게 하는 기능은 넣지 않았다 (FR-04 기획과 일치).
- **재검토 조건**: 같은 날 반복 학습이 필요하다고 판단될 때.

## DR-16. 표 구현: QTableView + 모델 (QTableWidget 사용 안 함)

- **배경**: 단어 목록 탭의 "새로고침"을 누르면 응답 없음이 발생했다. 2000행을 칸마다 항목으로 넣고 열 너비를 내용에 맞추는 방식이 원인이었다.
- **결정**: 단어 목록은 `WordTableModel`(QAbstractTableModel), 이력 표는 `ListTableModel`을 쓴다. 열 너비는 고정값이다.
- **결과**: 2000행 새로고침이 약 0.004초로 줄었다. 테스트 `test_word_list_refresh_is_fast_with_all_words`로 확인한다.
- **재검토 조건**: 열 너비를 사용자가 자동으로 맞추길 원할 때 (그때는 모델 기준 계산으로 구현).

## DR-17. 웹 버전 추가: Flask + HTML/JS, 로컬 전용 실행

- **배경**: 사용자가 exe 대신 웹페이지 형태의 프로그램을 원한다 (2026-11-04). PyQt 화면 계층은 웹 화면으로 대체해야 하지만, 단어·암기·시험·채점·보고서 로직은 재사용하고 싶다.
- **대안**
  - A. Flask(또는 FastAPI) + HTML/CSS/JS: Python이 DB와 로직을 맡고 브라우저가 화면을 그린다
  - B. Streamlit 또는 NiceGUI: Python만으로 화면 구현. 빠르지만 화면 제어와 상태 관리에 제약이 있다
  - C. 순수 정적 웹(브라우저 JS만): 서버가 필요 없지만 Python 로직을 JS로 다시 짜야 한다
  - 실행 범위: 로컬 전용(127.0.0.1) 또는 외부 공개(배포 서버, 로그인 설계 필요)
- **결정**: A안, 로컬 전용. 웹 진입점은 `src/run_web.py`, 서버는 `src/web/`, 화면은 `src/web/templates`와 `src/web/static`에 둔다. 서버 주소는 `127.0.0.1:5000`으로 고정한다.
- **근거**: 서비스 계층(`services`, `storage`, `quiz`, `study`, `report`)을 그대로 쓰므로 화면 계층만 바꾸면 된다. 개인 학습 기록이 외부에 노출되지 않는다 (NFR-07).
- **구현 메모**
  - 연속 학습일 계산을 `study/streak.py`로 옮겨 PyQt 없이도 쓰게 했다. `home_view.py`는 이 함수를 import한다.
  - `StudyService._load`를 공개 메서드 `load`로 바꿨다. 웹 API가 세션을 다시 불러올 때 쓴다.
  - 진행 중인 시험(`QuizRun`)은 서버 메모리(`app.config["QUIZ_RUNS"]`)에 둔다. 서버를 끄면 진행 중 시험은 사라지지만, 답한 문항은 DB에 남는다.
  - Flask 개발 서버는 `threaded=False`로 실행한다. 한 번에 한 요청만 처리해서 SQLite 연결을 여러 스레드가 나눠 쓰지 않게 한다.
  - 답하기 전에는 정답(`expected`, `accepted`)을 응답에 넣지 않는다.
- **제약**
  - 1인용 로컬 앱 전제다. 인증이 없으므로 외부 공개 전에 재설계가 필요하다.
  - 설정 API(`/api/settings`)의 키는 `daily_new_count`처럼 `config.json`과 같은 snake_case를 쓴다. 나머지 API는 camelCase를 쓴다.
  - 화면 기능은 데스크톱 MVP 범위만 옮겼다. TTS, 달력, 백업 등은 포함하지 않았다.
- **재검토 조건**: 외부 공개 또는 여러 사용자 지원이 필요해질 때 (인증, DB 연결 구조 재설계). PyQt 버전 폐기 여부는 웹 버전이 실사용으로 검증된 뒤 결정한다.
- **관련 결정**: DR-01 (GUI 라이브러리)은 웹 전환 이후 데스크톱 화면에만 적용된다.
